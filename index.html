The token tax

AI bills by the token. The same sentence in Kannada can cost many times more than in English.

BhashaToken measures that tax on 17 South Asian languages and 7 real tokenizers, rewrites each message into its cheapest form only if a multi-check verifier proves the meaning is unchanged, and records every decision so it can be audited.

What existed before, and what BhashaToken adds

Existing research (2023–2026)

  • Measures the tax (Petrov 2023; Srivastava 2026: 10 Indian languages, 6 tokenizers)
  • Picks one cheaper format for a whole task, for one model (RomanSetu 2024)
  • Fixes tokenizers (grapheme / vowel-sign aware) – needs retraining the model
  • Compresses prompts – shown to harm non-English text (Lost in Compression 2026)
  • Rarely checks that meaning survived; no per-request audit trail

BhashaToken (this project)

  • Works today with any hosted model: changes the text sent, not the tokenizer
  • Chooses per message and per model among 7 rewrites (no format always wins)
  • Meaning-safety verifier: numbers, dates, negation, questions, modality, names, every word – calibrated on held-out data
  • Decision trace + audit ledger: tokenizer hash, candidates, rejection reasons, latency
  • Statistics: confidence intervals, paired tests, ablations, failure taxonomy

Each turn is the next sentence of the same news story, professionally translated (FLORES-200). The AI keeps only the newest messages that fit in its memory (context window); older ones fade out. Why similarity alone is not enough

Held-out FLORES devtest sentences in 6 languages, each changed on purpose. Grey: share of unsafe changes a similarity-only check would let through. Orange: our full verifier. For safe rewrites, higher is better (they should be accepted).

Which check catches what

Ablation: remove one check at a time and measure how many unsafe changes still get caught. Checks with a big drop are doing real work.

Human evaluation

Download reviews (CSV)

Protocol (docs/METHODOLOGY.md): two native speakers rate each chosen rewrite for meaning (1–5), fluency (1–5) and "would you send it". Ratings are stored locally with the request's audit ID. We report only ratings actually collected.

What we found

      
    
    
    
    
    
      
    Limitations (stated honestly)
    
      
      
        
    1. Token counts are exact for the open tokenizer files; hosted APIs may add a few formatting tokens, and prices change. Costs shown are simulations.
      2. 
        
    2. Answer quality per format is not benchmarked; with Ollama installed, the Optimizer page shows a small local AI answering both versions (a demonstration).
      3. 
        
    3. The meaning verifier is rule-based and strict. It was tested on synthetic changes of the kinds it checks for; real errors outside these types (e.g. a wrong synonym) can pass, and some safe rewrites are wrongly rejected.
      4. 
        
    4. LaBSE embeddings are supported but optional; the default similarity is chrF on a common spelling, so paraphrases score low (conservative).
      5. 
        
    5. Casual romanisation is machine-made, not typed by users; we have not measured whether a model answers equally well in each format.
      6. 
        
    6. Grammar rules for compression cover Kannada, Tamil and Telugu pronouns only; the saving is small (a negative result we report).
      7. 
        
    7. Human evaluation needs native-speaker raters; the interface and protocol are built, results are shown only once collected.
      8. 
        
    8. Sinhala is not included yet. Sarvam-1's tokenizer is optional: python scripts/get_sarvam.py adds it to the live tools (non-commercial licence).

    Related work and exactly where we differ
    
    
    
      
    WorkWhat it doesWhat it does not do (our addition)
    
      
    Petrov et al. 2023; Ahia et al. 2023Show tokenizer premiums and unequal API cost across languagesNo South Asian per-message fix; we add 17 languages × 7 current tokenizers × two writing styles
    
      
    Srivastava 2026 (arXiv 2607.24276)10 Indian languages, 6 tokenizers; byte-token rate explains the tax (r = 0.89); context lossNative script only, no user-side mitigation, no meaning verification
    
      
    Token-cost ledger 2026 (arXiv 2609.00378)Splits token cost into removable and irreducible parts, includes KannadaNo rewriting, no per-input choice, no verification or audit
    
      
    RomanSetu 2024; Nag et al. 2024Romanisation / code-mixing can cut costOne format per task and model; we choose per message and per model and show romanising sometimes costs more
    
      
    Vowel Signs Are Not Letters 2026; grapheme tokenizers (ACL 2026)Find the vowel-sign split and fix the tokenizerRequires retraining; we explain it word by word and work around it for hosted models
    
      
    Lost in Compression 2026English-trained compressors harm other languages; only Hindi for IndiaRule-based compression for Dravidian languages with a verified safety budget
